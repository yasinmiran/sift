## Security & Privacy

- **1Password breached through an employee's GitHub account**: the password manager [says an attacker stole customer names and email addresses](https://1password.com/blog/update-on-nov-2026-security-incident) after reaching its backend systems. It began investigating on November 19, The Verge reports: the attacker took over an employee's corporate GitHub account, [read 1Password's source code and pushed malicious code to backend services](https://www.theverge.com/tech/1042409/1password-data-breach-leak) that downloaded customer data. Passwords and everything else stored in vaults were not exposed, and 1Password has not said how many customers are affected. Why it matters: the vault encryption held, which is the design working, but a list of confirmed password-manager customers is ideal phishing material, so treat any email claiming to be from 1Password with suspicion; one developer account was enough to ship code into production.
- **Microsoft: state hackers have adopted ARTEX**: state-backed groups in China and North Korea, including Salt Typhoon (the group behind earlier intrusions into telecom networks), have [added the AI penetration testing tool ARTEX to their arsenals](https://www.techmeme.com/261126/p3#a261126p3), The Record reports from a new Microsoft report. Earlier digests had ARTEX in the attack on the European Commission and suspected in a breach at US intelligence agencies; now Microsoft ties it to named government groups. Why it matters: software that probes networks for ways in without a human steering each step is now standard equipment for the best-resourced attackers, so defenders should assume probing at machine speed.
- **A 12-year-old remote root bug in Linux's NFS server**: OpenSec published [NFS2ROOT (CVE-2026-99362)](https://opensec.in/blog/nfs2root-cve-2026-99362), which it describes as a flaw in the kernel's NFS file-sharing server that gives an attacker root access over the network without logging in, present for 12 years. The same day a post to the oss-security mailing list [criticized Ubuntu's security response times](https://www.openwall.com/lists/oss-security/2026/11/25/9) as slow. Why it matters: a pre-authentication kernel bug is only as fixed as your distribution's patch speed, so if you export NFS shares, check your vendor's advisory and keep the service off untrusted networks.
- **Coding agents fix a vulnerability, then write it again**: across 14 task sequences, Codex, Claude Code and Qwen Code repaired a flaw 85.7% of the time when shown the failing security test, then [reintroduced the same class of flaw in a new session 26.7% of the time](https://arxiv.org/abs/2611.33519), about as often as agents that had never seen it (27.5%). Recording the fix in the agent's memory or supplying standard secure-coding rules did not close the gap; the authors' PRECEPT system, which rewrites those rules against the agent's own failures, lifted its weakest agent to 97.1% secure working code on unseen task types. Why it matters: agents can fix security bugs but do not learn from them, so a passed security review says nothing about the next session's code.
- **Models find new Windows kernel bugs in closed binaries**: DeepBinary, a [benchmark for open-ended vulnerability discovery](https://arxiv.org/abs/2611.33486), gives agents a disassembler and kernel debugger inside network-isolated virtual machines and replays every crash report on a fresh machine. Across 12 Windows kernel binaries, models including GPT-6 Sol, Claude Opus 5 and DeepSeek V4.1 Flash found over 200 vulnerabilities, 146 of them previously unknown, worth an estimated $661,000 in bug bounties. Why it matters: most security benchmarks test open source code with known bugs; this one shows the same agents producing new findings in software nobody outside the vendor has source for.
- **Backblaze's new privacy policy allows selling data to advertisers**: the backup and cloud storage company's policy taking effect next month says it [may sell certain personal information to advertisers](https://arstechnica.com/information-technology/2026/11/backblaze-explains-why-its-sharing-customer-information-with-advertisers/), Ars Technica reports; the current policy promises never to share addresses or emails for marketing without consent and does not mention advertisers. Why it matters: customers chose a backup provider to hold their files, not to become an ad audience, and the change arrives as a policy edit, not a product decision anyone opted into.
- **MiniMax: confidential data accessed despite no-retention requests**: a researcher at the security firm Dragos told Reuters that unidentified parties [accessed confidential data submitted to MiniMax](https://www.techmeme.com/261126/p7#a261126p7), the Chinese AI startup, even after users had asked the company not to store or retain it. Why it matters: a "do not retain" setting is a promise, not a mechanism; anything sent to a hosted model should be treated as stored unless the provider can prove otherwise.
- **Google will publish Android developers' addresses**: from next year many Play Store developers must [display a phone number and address publicly](https://www.theverge.com/tech/1043228/android-play-store-google-developer-address-eu), The Verge reports. The rule comes from the EU's Digital Services Act, but Google says the details will be public worldwide; developers have until February 1, 2027 to declare whether they count as a "trader", which broadly means earning revenue from their apps. Why it matters: for a solo developer working from home, the business address is the home address, so a consumer-protection rule becomes a doxxing risk.
- **Chatbot companions, children and what happens to the data**: 42 state attorneys general [oppose Character.AI's plan to auction data](https://www.techmeme.com/261125/p41#a261125p41) from more than 21 million US accounts, over 2.1 million of them registered to minors, saying the sale lacks user protections, TechCrunch reports. Apple [removed MiniMax's chatbot app Talkie](https://www.techmeme.com/261125/p44#a261125p44) from the App Store worldwide over sexual content after the Bureau of Investigative Journalism and partner outlets showed it evidence of AI characters sexualizing children. And New York governor Kathy Hochul [signed a five-year ban on AI chatbot toys](https://www.techmeme.com/261125/p37#a261125p37) starting in February, following California's four-year ban in September. Why it matters: private conversations with a companion bot are an asset that can be sold when the company fails, and regulators are now moving on the product category itself, not only on individual apps.
- **Also**: The Hacker News reports that the North Korea-linked PolinRider campaign [poisoned more than 7,600 GitHub repositories](https://thehackernews.com/2026/11/north-korea-linked-polinrider-poisons.html?m=1) to spread malware; and X [rolled out its first parental controls](https://www.theverge.com/news/1043078/x-parental-controls-features): parents can see time spent, set daily limits and approve new followers, but cannot read messages or see searches, and every change is visible to the teen.

## Devtools & Infra

- **Vercel rebuilds its Workflow engine around speculative execution**: [Workflow SDK 5.8](https://vercel.com/changelog/workflows-speculative-execution) cuts the overhead between steps of a durable workflow from 85 ms to 7 ms at the 75th percentile, and a 256-step parallel fan-out adds 2.5 seconds of overhead where it added 13.5. The speed comes from running steps before the engine is sure they are needed, so it applies only to steps that are safe to repeat; steps that must run at most once need `maxRetries = 0`. Why it matters: agent loops are chains of small steps, so per-step overhead is most of the wait, but the upgrade quietly makes idempotency (safe re-runs) a requirement to audit before you bump the version.
- **GitHub merges Copilot's three inline models into one**: a [paper from the Copilot team](https://arxiv.org/abs/2611.33314) describes replacing separate completion, nearby-edit and long-distance-edit models with a single model that emits a list of anchored patches. In live A/B tests the first phase cut time to display by 6.77% and output tokens by 58.93%, and the full version reduced dismissed suggestions per user by 10.06%. Why it matters: one response can now carry several related edits across a file, which is what makes inline suggestions feel like a refactor instead of autocomplete.
- **Also**: [Pydantic launched Pax](https://pydantic.dev/articles/pax-harness-beta), a terminal coding agent built from swappable plugins, alongside a beta of its agent harness; [Zed 1.30](https://alphasignal.ai/news/zed-1-30-trims-its-interface-and-cuts-gpu-usage-for-developers) adds a hideable title bar and per-repository model choice for AI commit messages; and Cognition's [Org Charts view](https://alphasignal.ai/news/cognition-adds-org-charts-to-devin-bots-managing-2-000-weekly-pull-requests) shows every Devin bot and its running sessions on one canvas.

## Research

- **OpenAI's batch is bigger than the 9/4 paper, and Anthropic shrinks the Riemann proof**: the release behind yesterday's matrix multiplication entry is [nine manuscripts](https://github.com/openai/math/blob/main/history.md), each with machine-checked (Lean) proofs of selected results. Beyond 9/4 they claim tight bounds for the Fourier transform and integer multiplication, a strongly polynomial algorithm for linear programming (a running time that depends only on the number of variables and constraints, the question Stephen Smale listed as his ninth problem), and a [disproof of the polynomial Hirsch conjecture](https://github.com/openai/math/blob/main/preprints/Superpolynomial-graph-diameter-of-simple-polytopes-November-24-2026/paper.pdf), the hope that any two corners of a polytope are a short walk apart, which bears on how fast the simplex method can be. OpenAI calls the collection (730 manuscripts, about 42% of headline results formalized) "raw research data" and says unformalized results could have issues. Separately, an Anthropic researcher posted a [shorter Lean proof of the Riemann hypothesis](https://github.com/lsernau/grh-lean) and its generalization to Dirichlet L-functions, based on the Alpöge and Claude proof: a readable edition of about 300,000 lines and a compact one of about 76,000, against the original's 17 million. Its README is plain that the proof has passed machine checks only and that no mathematician has read it through. Scott Aaronson's [reaction post](https://scottaaronson.blog/?p=10379) describes "a whole new continent of mathematical truth". Why it matters: none of this is refereed, and Latent Space notes OpenAI's log already records three October withdrawals over a sign error, but a 200-fold shorter proof is the first step toward people being able to read what the machines have checked.
- **Google's agent claims a proved running time for factoring**: a preprint in Google Research's repository claims an [unconditional subexponential algorithm for factoring integers](https://github.com/google-research/google-research/tree/4a7bc8ab0bc770e71a259b7966c500496b99010a/cogentic_research_papers/integer_factorization): a randomized method that always returns a correct answer, with expected running time proved without relying on any unproven number-theory hypothesis. The README says the paper came from Cogentic, Google's agent framework for mathematics, running on Gemini 4 with no human input beyond the initial prompt, and that a Lean formalization is finished but will be released separately. The claimed bound has the same shape as the number field sieve, the fastest known factoring method, whose speed has only ever been argued heuristically; its constant (105) is far larger, and the README claims no practical speedup. Techmeme's summary of Scott Aaronson's post, linked above, adds that his sources say leading labs hold unreleased algorithmic results that could break deployed cryptosystems, their nature unknown. Why it matters: this is a claim about proof, not a new attack on RSA, and it is unchecked by anyone outside Google; but factoring is the problem much of deployed encryption rests on, so machine-made number theory arriving here is the part of the proof wave security people will watch.
- **A famous medical dataset has had a column backwards for decades**: the UCI Heart Disease data, a standard machine-learning benchmark, [stores its chest-pain variable in reverse of its documentation](https://arxiv.org/abs/2611.33248): the code labeled "asymptomatic" marks patients with typical angina. Ordinary models are unaffected, since they do not read labels, but in a sample of explainability papers 25 of 32 that interpreted the category got its direction wrong, and language-model classifiers that read the labels lost 0.12 to 0.33 in AUC (a standard accuracy score). Why it matters: accuracy metrics cannot catch a mislabeled column, so the error surfaced only in work that tried to explain the model, and none of 124 papers checked had noticed.
